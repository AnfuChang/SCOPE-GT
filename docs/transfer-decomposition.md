# Table IX transfer controls

The decomposition modules complement the native and SCMB runs from
`scripts/run_transfer.sh`. They retain the supplied backbone recipes and use the
same training, checkpoint-selection and final-prediction worker. Compatible NPZ
adapters are bundled in `Baselines/`; `SCOPE_GT_BASELINES_ROOT` can override them.

| Paper label | CLI variant | Launcher | Computation |
|---|---|---|---|
| FQ | `native` | `run_transfer.sh` | Native full-query attention |
| FQ-LG | `native_packed` | `run_transfer_decompose.sh` | Native attention grouped by exact sequence length, without padding |
| CQ-U | `cq_noshare` | `run_transfer_decompose.sh` | Packed center-query reads with per-sequence encoding and K/V |
| CQ-E | `cq_sharedenc` | `run_transfer_decompose.sh` | Shared input encodings with per-occurrence K/V; optional finer control |
| SCMB | `scmb` | `run_transfer.sh` | Shared input encodings and base K/V |

HubGT and SwapGT inputs have fixed lengths. FQ-LG equals FQ for those backbones,
so the launcher skips it. `center_padded` remains an older diagnostic and is not
the paper's padding-free CQ-U. Keep `--v1-pad-multiple 1` for exact-length FQ-LG.

## Run and summarize

From the repository root, set `DATA_BASE` to the processed dataset directory:

```bash
SEEDS="0 1 2 3 4" OUT=results/transfer bash scripts/run_transfer.sh
SEEDS="0 1 2 3 4" REFERENCE=results/transfer \
  OUT=results/transfer_decompose bash scripts/run_transfer_decompose.sh \
  --variants native_packed cq_noshare
python -m SCOPE_GT_transfer.decompose_report \
  --results results/transfer_decompose/nlgt results/transfer_decompose/gophormer \
            results/transfer_decompose/hubgt results/transfer_decompose/swapgt \
  --reference results/transfer --out results/transfer_decompose/summary
```

Omit the explicit `--variants` argument to also run the optional CQ-E control.
The shell and Python decomposition launchers default to five seeds, `0 1 2 3 4`,
matching the native/SCMB launcher. Use the same seed list and any configuration
overrides in both launchers. A legacy single-seed run remains reproducible with
`SEEDS="1"` or `--seeds 1`. Changing the launch default does not add seeds to
previously saved results; rerun missing seeds before reporting five-seed means.
The report only
includes reference seeds covered by the decomposition runs, and reports pairing
checks. An incomplete arm stays marked incomplete. No experiment results are
bundled or regenerated by installing these modules.

Train/validation, preprocessing and whole-job watchdogs default to `0` (disabled)
in both transfer launchers. Explicit `--epoch-timeout`, `--preprocess-timeout`
and `--job-timeout` arguments can opt into limits; no 3,600/7,200-second limit is
implicitly applied to a transfer run. Runtime-probe timeouts are separate.

Inspect the plan without training:

```bash
SEEDS="0 1 2 3 4" bash scripts/run_transfer.sh --dry-run
SEEDS="0 1 2 3 4" bash scripts/run_transfer_decompose.sh --dry-run
```

`python -m SCOPE_GT_transfer.decompose_check --help` documents a deterministic
equivalence check on one batch from processed inputs. It runs no training.
`scripts/schedule_transfer_decompose.sh` optionally queues the same controls on
two GPUs; invoke it explicitly when a scheduled server run is desired.
